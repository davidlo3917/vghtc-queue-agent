PROPOSED SCHEME ・ 應用情境

三個情境，一個 LINE 介面

S1

掛號前查詢

這位醫師平常多快、常在幾點卡住、通常幾點看完

S2 ・ 核心

掛號後訂閱

給診間、午別、號碼、交通時間；Agent 監看、預測、在該出門時推播

S3

變化提醒

代診、延誤、速度異常、已叫到、診次結束時重新推理並通知

不掛號、不換診、不碰個資；所有提醒都是建議，使用者可按「我到了」「已叫到」。

範圍刻意收斂：不碰掛號系統、不碰個資。S2 是核心，S1 和 S3 是 S2 的資料和迴圈自然延伸出來的。可在開診前訂閱，診次出現後才開始預測。系統無法得知使用者是否已報到，所以所有提醒皆為建議。
